Лабораторна робота No1
“Підготовка проєкту вебзастосунку: технічне завдання, сценарії, Trello та репозиторій”
Мета роботи: навчитися формулювати вимоги до вебзастосунку, визначати його сторінки й ролі, створювати сценарії користувачів, планувати роботу в Trello та готувати репозиторій проєкту.
Завдання 1
1) назву та короткий опис проєкту
Campus – це вебзастосунок дошки оголошень для учасників освітнього процесу, де користувачі можуть публікувати та знаходити оголошення про купівлю або продаж вживаних товарів: техніки, меблів, тощо.
2) проблему, яку вирішує вебзастосунок
Полегшує процес покупки Б/В товарів, та полегшує процес для продавця продати товар.
3) мету проєкту та цільову аудиторію
Створити веб-застосунок де покупець і продавець можуть легко знайти один одного. Цільова аудиторія: учасники освітнього процесу.
4) ролі: гість, користувач, модератор, адміністратор
Ponі: гість, користувач, модертор, адміністратор.
Гість може:
1. Відвідати головну сторінку та інші спільно доступні сторінки.
2. Переглядати оголошення без відображення контактів.
3. Створити аккаунт.
4. Залогінитись.
Користувач може:
1. Відвідати головну сторінку та інші спільно доступні сторінки.
2. Переглядати оголошення з відображенням контактів.
3. Створити/редагувати/видалити свої оголошення.
4. Редагувати свій профіль.
5. Просувати свої оголошення на платній основі.
6. Писати та отримувати публічні відгуки як продавець та як покупець.
7. Подати скаргу на оголошення.
	Модератор може:
1. Відхиляти оголошення, які порушують правила.
2. Змінювати статус скарги на оголошення: схвалено, відхилено, розглядається.
3. Вести документ рішень, які були прийняті щодо скарг.
Адміністратор може:
1. Блокувати або розблоковувати користувачів.
2. Призначати модераторів або забирати цю роль.
3. Змінювати загальні налаштування системи.
5) перелік основних функцій
1. Реєстрація та авторизація користувачів.
2. Створення, редагування та видалення оголошень.
3. Головний екран з пошуком та сортування оголошень за фільтрами.
4. Категорії оголошень.
5. Особистий профіль в якому всі виставленні оголошення користувача та його данні котрі користувач може змінювати.
6. Сторінка оголошення з контактами для користувачів та сторінка без контактів для гостей.
7. Платне просування оголошень.
8. Опрацювання скарг та модерація оголошень.
9. Панель адміністратора.
6) функціональні й нефункціональні вимоги
Функціональні:
1. Система має розмежовувати права доступу за ролями: гість, користувач, модератор, адмін.
2. Кожне оголошення належить окремій категорії.
3. Скарга на оголошення потрапляє до черги у модерацію.
4. Публікація, редагування та видалення оголошення доступні лише авторизованому користувачу який є власник цбого оголошення.
5. Гість переглядає оголошення без контактів продавця, а контакти бачить лише авторизований користувач.
6. Каталог має підтримувати пошук, фільтрацію за категорією.
Нефункціональні:
1. Підтримка актуальних версій браузерів Chrome та Edge.
2. Паролі зберігаються у хешованому вигляді.
3. Дані передаються через HTTPS.
4. Мова інтерфейсу українська з можливістю змінити на іншу.
5. Час відгуку сторінок не більше 2 секунд.
7) обмеження проєкту
1. Проєкт має бути готовий до кінця першого семестру.
2. “Застосунок” працює лише як вебсайт без застосунку мобільного/декстоп.
3. Розгортання має бути на вебхостингу PythonAnywhere та локально localhost.
4. Серверна частина реалізована на Python 3.14
8) критерії готовності першої версії
1. Усі основні сторінки відкриваються та коректно відображаються.
2. Працює навігація сіж сторінками.
3. Працює реєстрація та вхід.
4. Повний цикл оголошення від створення до видалення.
5. Працює каталог пошуку та фільтри.
6. Права ролей розмежовані.
7. Можна подати та опрацювати скаргу.
